# План корректировки промпта и кода

Дата: 2026-10-06. Основание: разбор `PROMPT.txt` по задаче из `docs/prompt_tast.md`, согласован в диалоге 06.10 (владелец принял замечания до составления плана).
Язык инструкций промпта: оставить английский (текущий `PROMPT.txt` — английский; перевод на русский в плане был черновым; тезис «кириллица дороже в токенах» не замерен для Gemini — рискованное изменение стоимости каждого запроса не вносим).
Аудит `docs/audit.md` (не источник истины) разобран 06.10, подтверждённые пункты учтены ниже; решения владельца 06.10 по спорным П4/П8 внесены (см. П4, П8).
Цель: убрать противоречия и дрейф саммари, не раздувая промпт. Код — только точечные фиксы, без рефакторинга.

## Рамки

Делаем:
- правки `PROMPT.txt` (пункты П1–П10 ниже);
- два фикса в `main.py` (пункты К1–К2): сортировка и сохранение родителей.

Не делаем (сознательно отложено владельцем):
- строку «это часть N из M» в промпт;
- второй проход ИИ для дедупликации заголовков чанков — каждый вызов на счету, дубли не критичны;
- рефакторинг «заодно», правки рантайма вне пунктов К1–К2.

## Правки PROMPT.txt

Общий принцип: объём не растёт — дубли и частные примеры уходят, их место занимают недостающие лимиты из задачи.

**П1. Одна шапка вместо трёх (строки 1–10).**
Было: Role + Task Execution + Task Overview тремя блоками об одном.
Стало: один блок из двух фраз («Ты группируешь сообщения по темам и пишешь сжатое саммари с цитатами. Вывод — только готовый текст по шаблону.»).
Причина: один приказ — одно поведение.

**П2. `chat_name` (строка 16).**
Было: «chat display name (use in summary header)».
Стало: в Input Specification перечислить только фактический состав анализа — «metadata: chat_id, period_start»; упоминания `chat_name, export_date, total_messages, filtered_messages` убрать (а не помечать «игнорируй»); маркер «JSON v2.0» убрать.
Причина: все четыре поля в анализ не попадают (добавляются только в экспорте `/copy` без ИИ, `main.py:3626–3632`; анализ — `main.py:2020,2182,2204`, состав metadata — `main.py:1597–1600`), инструкция про отсутствующие поля тратит токены.
Альтернатива (не выбрана): реально передавать `chat_name` в анализ и дать заголовок в шаблоне.

**П3. Транслитерации (строка 24).**
Было: частные примеры ProMint/проминт, Aster, Uniswap, JUP, Monad.
Стало: правило «варианты написания одного имени (латиница/кириллица, сокращения, регистр) считай одним именем».
Причина: частный словарь крипточата в общем боте сужает модель.

**П4. Правило 2+ ответов (строка 36) — решение владельца 06.10: оставить обязательным.**
История: правило добавлялось и ужесточалось владельцем трижды (`96bb7ff` 31.05, `4a18d77` 01.06, `3e058cd` 02.06 — «Never merge a reply chain into another topic»).
Формулировка владельца: «цепочка ответов (поле r) — сильный сигнал, обязательно отдельная тема.»
Реализация: строку 36 не менять (MANDATORY-правило сохраняется как есть).
Дополнительно в промпт (Step 1) добавить: «если родителя с id из поля r нет в массиве — используй r только как сигнал связи, не цитируй отсутствующее» (висячие `r` возможны всегда: родитель без текста пропускается, `main.py:1437`; лимит догрузки 50, `main.py:1429`).
Воротник снят решением владельца; обратный регрессионный контроль из проверки остаётся.

**П5. Гранулярность (строка 46).**
Было: «только EXACT same, смежное — отдельно».
Стало: «одна тема = один вопрос/сущность/событие; смежное — отдельно, только если обсуждается другой предмет (вывода/консенсуса может и не быть)».
Причина: граница через предмет проверяема и покрывает темы без консенсуса (Step 3 допускает «no consensus», `PROMPT.txt:53`).

**П6. URL-правило (строка 38).**
Было: обрывочная фраза «новость со ссылкой, даже с минимумом текста» без действия.
Стало: «новость/пост со ссылкой — отдельная тема, даже при минимуме текста».
Причина: незаконченное правило модель додумывает по-своему.

**П7. Минимальный кластер (строки 42–44).**
Было: «substantial argumentation (2+ sentences each)» — непонятно, на сообщение или на автора.
Стало: «2+ осмысленных сообщения от 2+ участников, либо 1 автор с 2+ содержательными предложениями или ссылкой».
Причина: устраняет двусмысленность «each».

**П8. Исключения (строки 48–50) — решение владельца 06.10: пункт про оскорбления НЕ добавлять; чистку дублей с кодом делать.**
Шум: из промпта убрать только то, что действительно дублирует код (`is_noise_message`: короче 3 символов, `MIN_MESSAGE_LENGTH`, `main.py:278,1118`; паттерны `+/-`, «ок/ok/лол/да/нет», пунктуация, эмодзи, `NOISE_PATTERNS`, `main.py:279–284`) — т.е. примеры 'ok', '+' из строки исключений убрать. Исключения «одиночные one-liners/шутки/ремарки без ответов» и «bot messages» сохранить в промпте: код их не режет (`EXCLUDED_USERS` — ручной список без автодетекции ботов, `main.py:692,928,1181`), а пункт введён владельцем осознанно (`7f3c55c` 04.06).
Причина: меньше дублей с кодом, без возврата проблемы коммита `7f3c55c`.

**П9. Цитаты (Шаг 4, строки 55–62).**
- Добавить недостающий лимит задачи: «не более 2 цитат одного автора в теме» (рядом с «максимум 5 участников»; слово «ссылки» для цитат не использовать — «внешняя ссылка» только про URL внутри сообщения).
- Зафиксировать формат: «цитата: пересказ сути одной фразой; дословно в кавычках — только термин/цифру».
- Длинные (>200 символов): «сожми до одной фразы, внешнюю ссылку сохрани».
- «Preserve original terminology» оставить как есть.
Причина каждого: лимит держит размер темы; один формат убирает дрейф «цитата/пересказ»; ссылка не теряется при сжатии.

**П10. Плейсхолдеры и CRITICAL (строки 64–79).**
- Плейсхолдеры: заменить абстракцию на «ссылка вида `[имя из поля s](https://t.me/c/CHAT_ID/MSG_ID)`, значения бери из сообщения» + живой пример (текущий пример `SomeUserName...193/546` оставить).
- CRITICAL: функцию оставить (ошибки были в проде), форму сжать с 5 строк-дублей до 1–2 («Верни только текст по шаблону. Без JSON и блоков кода.»). Дубликат в коде (`main.py:1979`) не трогать.
Причина: пример вместо абстракции + один запрет вместо пяти.

## Правки main.py

**К1. Детерминированная сортировка (`collect_messages`, `main.py:1411–1456`).**
Было: `reverse()` затем `sort(key=date-строка)`.
Стало: сортировка по `(date, message_id)` в обоих местах + предсказуемый отбор родителей `sorted(missing_ids)[:50]` (лимит 50 не меняется).
Причина (честно): укрепление детерминизма, а не фикс доказанной нестабильности — `reverse()` детерминированного `iter_messages` и стабильный `list.sort` уже воспроизводимы; реальная шероховатость — отбор из множества (`main.py:1429`) скачет при изменении набора.

**К2. Не терять родителей (`collect_messages` + `optimize_messages`, `main.py:1425–1457,1156`).**
Было: догруженные родители (лимит 50) потом могут быть выкинуты `optimize_messages` как шум/исключённые → поле `r` висит в воздухе.
Стало: родителя, на которого есть ссылка из выборки, не выкидывать как шум/исключённого (метка внутренняя, в памяти, в JSON не попадает — контракт промпта и состав полей `build_optimized_json_structure`, `main.py:1584–1594`, не меняются); для этого передать в `optimize_messages` (`main.py:1156`, вызов `main.py:3191`) множество id, на которые есть ссылки.
Ограничение: висячие `r` полностью не устраняются (родитель без текста — `main.py:1437`, свыше лимита 50) — модель инструктируется строкой из П4.
Причина: целая цепочка кластеризуется лучше оборванной.
Лимит 50 не трогать.

## Проверка

- Обязательно: `./venv/bin/python tests/test_run_once.py` — должен остаться зелёным (покрывает дежурство, но не К1/К2: `collect_messages`/`optimize_messages` в сюите отсутствуют — проверено поиском, 0 совпадений; поэтому добавить 2–3 unit-теста в духе репозитория: `optimize_messages` сохраняет родителя, на который есть `r`; порядок после сортировки = (date, id)).
- Ручная (два прогона, цена — квота Gemini ~20 запр/день/ключ, многочанковое саммари = несколько запросов на прогон): один фиксированный массив — диапазон id (`/sum 600-800`) на фиксированном чате; прогнать дважды; критерий — тот же набор тем и цитат (±формулировка заголовка, дословное совпадение при `GEMINI_TEMPERATURE=0` не требовать); проверить отсутствие оскорблений в цитатах; обратный контроль П4 — цепочка с 2+ ответами видна отдельной темой, а не растворена.
- Контроль объёма: по `prompt_tokens` контрольного запроса (код уже считает `total_usage['prompt_tokens']`), а не по символам — символы ≠ токены при смене языка.
