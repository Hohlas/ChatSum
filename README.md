# ChatSum

Открываешь чат после пары дней тишины — а там уже тысяча новых сообщений.
Одна команда — и вместо бесконечной ленты получаешь стройный разбор:
всё разложено по темам, сжато до сути, каждый вывод подкреплён цитатой.
Бежишь глазами по заголовкам, останавливаешься только на важном.
Захотел подробностей — читаешь короткие выжимки из слов участников
и по ссылке прыгаешь точно к месту спора в чате.

Тысячи сообщений в чате — одна команда, и получаешь аккуратный разбор:
главные темы, кто что говорил, важные ссылки и цифры. Не надо листать
чат за неделю — бот прочитает всё сам и разложит по полочкам.

## Что он умеет

- **Саммари за период:** «что было в чате за последние 12 часов / 2 дня».
- **Саммари по количеству:** «разбери последние 50 сообщений».
- **Саммари по расписанию:** каждое утро получаешь дайджест чата сам, без команд.
- **Выгрузка без нейросети:** сохранить переписку текстом, чтобы разобрать вручную.

живого саммари ([полный разбор](https://telegra.ph/Sammari-chata-vajbkodery-10-04-4)):

<details>
<summary>Режим «размышления» модели (reasoning_effort: none / low / medium / high)</summary>

Перед ответом модель может «думать» — тратить время и токены на внутренние
рассуждения. Режим задаёт их объём: `none` — без раздумий, `high` — максимум.
Чем глубже разбор, тем больше тем он вылавливает, но тем чаще появляются
повторы и мелкие темы.

Замер на реальном чате (~550 сообщений, один и тот же вход):

| Режим | Тем | Мышление, токенов |
|---|---|---|
| none | 22 | 0 |
| low | 29 | 2 044 |
| medium | 36 | 16 378 |
| high | 57 | 49 145 |

- `none` — аккуратно и компактно, но теряет часть мелких обсуждений.
- `low` — небольшой прирост покрытия.
- `medium` — заметно полнее.
- `high` — вдвое больше тем, но могут появляться повторы.

Режим задаётся строкой `GEMINI_REASONING_EFFORT`; на своём сервере
изменения применяются после `/reload_config`, 
в GitHub Actions — после коммита файла в репозиторий.

</details>

## Основные команды

```text
/sum 12h     — что было в чате за последние 12 часов
/sum 2d      — за последние 2 дня
/sum 50      — последние 50 сообщений
/copy 100    — сохранить последние 100 сообщений без анализа (бесплатно)
/sch ...     — настроить ежедневный дайджест (только на своём сервере)
```

Команду пишешь прямо в нужном чате — бот работает с твоего аккаунта.
Сама команда из чата исчезает, а результат приходит в твой канал результатов
(или в «Избранное», если канал не задан). Суффикс `+` дополнительно копирует
результат в исходный чат.

<details>
<summary>Расширенный список команд</summary>

```text
/sum            — за последние 24 часа
/sum 3h        — за последние 3 часа
/sum 2d        — за последние 2 дня
/sum 45        — последние 45 сообщений
/sum 600-800   — сообщения с 600-го по 800-е от конца
/sum 2d-3d     — сообщения от 3 до 2 дней назад
/sum 1d+       — анализ + копия результата в исходный чат
/sum 1d-       — вместо Telegraph прислать как сообщение Telegram
/sum1d+-       — пробел не обязателен, + и - можно вместе

/copy 3h | /copy 50 | /copy 600-800 | /copy 2d-3d
               — то же, но выгрузка без анализа (бесплатно):
                 JSON-файл + текст для ручного разбора
/help          — справка
```

Настройки и расписание на своём сервере — командами в чате:

```text
/config /show_model /show_excluded /show_priority /show_prompt
/add_excluded НИК /remove_excluded НИК
/add_priority НИК /remove_priority НИК
/set_model НАЗВАНИЕ
/set_provider google|openrouter|nvidia
/reload_config
/sch 09:00 1d    — дайджест каждый день в 09:00 МСК
/sch 21:30 12h   — то же на 21:30 с охватом 12 часов
/sch 09:00 1d+   — + копия в исходный чат, - как сообщение Telegram
/sch_list /unsch
```

Часть настроек в GitHub Actions командой не меняется: правки файлов (`/sch`,
`/unsch`, `/set_model`, `/set_provider`, `/add_excluded`, `/remove_excluded`,
`/reload_config`) там живут только в репозитории и пушатся коммитом. Разбор
(`/sum`, `/copy`), `/help`, `/config` и `/show_*` работают и в дежурстве —
пока дежурный на связи. Расписание задаётся файлом `SCHEDULE.txt` (см.
установку), а менять его можно прямо из Telegram сообщением без слеша
(`08:00 sum1d t.me/имя_чата`, `sch`, `unsch`, `help`).

</details>

## Два способа запуска

|  | Свой сервер (VPS) | GitHub Actions (без сервера) |
|---|---|---|
| Что нужно | Компьютер или сервер, который всегда включён | Только аккаунт GitHub, сервера не надо |
| Как работает | Бот постоянно на связи, отвечает сразу | Бот просыпается по расписанию и почти всё время на связи дежурным |
| Команды | Прямо в любом чате: `/sum 12h` | В канале результатов, без слеша: `sum50 t.me/имя_чата` |

Можно только один способ за раз — оба сразу не работают: два живых бота
на одной сессии Telegram мешают друг другу и могут сломать вход в аккаунт.

## Установка

Оба способа начинаются одинаково: **подготовьте компьютер → получите ключи
Telegram → получите ключ Gemini → заполните `private.txt`**. Это первые четыре
спойлера ниже. После них выберите один из двух вариантов и откройте его спойлер.
Ничего программировать не нужно: все команды копируются в терминал как есть.

<details>
<summary>1. Подготовьте компьютер (git, Python 3.10+, редактор текста)</summary>

Понадобятся три вещи:

1. **git** — программа, которой скачивают код. Проверка: `git --version`
   (должна напечататься версия, например `git version 2.43.0`).
   Установка: Linux (Ubuntu/Debian) — `sudo apt install -y git`,
   Windows — [git-scm.com/download/win](https://git-scm.com/download/win),
   macOS — `xcode-select --install`.
2. **Python 3.10 или новее.** Проверка: `python3 --version`.
   Установка: Ubuntu/Debian — `sudo apt install -y python3 python3-venv python3-pip`,
   Windows — [python.org/downloads](https://www.python.org/downloads/) (при установке
   поставьте галочку «Add python.exe to PATH»), macOS — `brew install python`.
3. **Редактор текста**, чтобы заполнить файл с ключами. На Linux/Mac проще всего
   встроенный `nano`: `nano private.txt`, сохранить — `Ctrl+O`, `Enter`,
   выйти — `Ctrl+X`.

Для варианта 2 (GitHub Actions) дополнительно нужен аккаунт GitHub и утилита
`gh` (о ней — в спойлере варианта 2).

Всё остальное на этом шаге делать не надо — установщик ниже сам поставит
Python-библиотеки в отдельную папку `venv` внутри проекта.

</details>

<details>
<summary>2. Telegram: api_id и api_hash (бот через BotFather НЕ нужен)</summary>

Здесь нужен не отдельный бот, а приложение в системе Telegram:
программа входит от твоего имени (такой запуск называется «userbot» —
программа действует как твой аккаунт). Шаги по официальной справке
([core.telegram.org/api/obtaining_api_id](https://core.telegram.org/api/obtaining_api_id)):

1. Поставь официальный клиент Telegram и зарегистрируйся.
2. Открой [my.telegram.org/auth](https://my.telegram.org/auth) и войди по номеру
   телефона (код придёт в Telegram).
3. Раздел `API development tools` → заполни короткую форму
   (название и платформа — любые) → получишь `api_id` (число)
   и `api_hash` (строка).
4. Впиши их в `private.txt` вместе с номером телефона в виде `+7999...`.

Помни: один номер — одно приложение; важные письма разработчика приходят
на этот номер. Ключи никому не показывай: зная `api_id`, `api_hash` и код
подтверждения, чужой человек может войти в твой Telegram.

</details>

<details>
<summary>3. Gemini: бесплатный ключ для gemini-3.8-flash</summary>

1. Открой [aistudio.google.com/apikey](https://aistudio.google.com/apikey)
   и войди Google-аккаунтом.
2. Нажми `Create API key`, выбери или создай проект — ключ вида `AIza...`
   появится на странице ключей (справка:
   [ai.google.dev/gemini-api/docs/api-key](https://ai.google.dev/gemini-api/docs/api-key)).
3. Вставь ключ в `private.txt` как `GOOGLE_API_KEY`. Для запаса лимита
   добавь ещё: `GOOGLE_API_KEY1`, `GOOGLE_API_KEY2`... — бот крутит их по кругу.
4. Модель уже выбрана в файле `MODEL_CONFIG.txt` (строка
   `GEMINI_MODEL=gemini-3.8-flash`) — в `private.txt` её писать не надо.

Старт бесплатный: токены входа и выхода на бесплатном уровне не тарифицируются
(цены — [aistudio.google.com/docs/pricing](https://aistudio.google.com/docs/pricing)).
Учти: на бесплатном уровне содержимое могут использовать для улучшения продуктов.

Там же в `MODEL_CONFIG.txt` можно переключить бота на другие сервисы
(OpenRouter, NVIDIA) — строкой `LLM_PROVIDER` и ключами `OPENROUTER_API_KEY` /
`NVIDIA_API_KEY` в `private.txt`; по умолчанию выбран Gemini, и ничего менять
не нужно.

</details>

<details>
<summary>4. Заполните private.txt (файл с ключами)</summary>

`private.txt` — единственный файл, который **не** лежит в общем репозитории:
он прописан в `.gitignore`, поэтому ключи не попадут на GitHub. Файл появится
сам после `./scripts/setup.sh` (копия `private.txt.example`).

Минимум (первый запуск на своём сервере) — четыре строки:

```env
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
TELEGRAM_PHONE=+79991234567

GOOGLE_API_KEY=AIzaSyExampleKey
```

Запас лимита Gemini (чем больше ключей, тем реже упираешься в суточный потолок):

```env
GOOGLE_API_KEY1=AIzaSy...
GOOGLE_API_KEY2=AIzaSy...
```

Канал для результатов (необязательно, но так удобнее):

```env
TELEGRAM_GROUP_ID=-1002...
```

- Если `TELEGRAM_GROUP_ID` не задан, результаты пойдут в твоё «Избранное».
- Если задан канал-форум, бот сам заведёт в нём отдельную тему на каждый чат.
- Как узнать ID — спойлер «Справка: канал для результатов» внизу.
- Модель, температура и режим размышления живут в `MODEL_CONFIG.txt`, а не здесь.

**⚠️ Важно:** значения после `=` не заключай в кавычки, не оставляй пробелов
вокруг `=` и не пересылай этот файл никому.

</details>

<details>
<summary>Вариант 1. Свой сервер (VPS) — пошагово</summary>

Понадобится машина, которая не выключается: VPS (арендованный сервер, от ~200 ₽
в месяц) или всегда включённый домашний компьютер с Linux.

**Шаг 1. Подключитесь к серверу и скачайте код.**

```bash
ssh ваш_логин@адрес_сервера        # если это удалённый сервер; пароль выдаёт хостер
git clone https://github.com/Hohlas/ChatSum.git
cd ChatSum
```

**Шаг 2. Запустите установщик.**

```bash
./scripts/setup.sh
```

Он проверит Python, создаст папку `venv`, поставит туда библиотеки и сделает
файл `private.txt` из образца. Скрипт можно запускать повторно — он лечит
сломанное окружение.

**Шаг 3. Заполните `private.txt`** (ключи из шагов 2–3 и, при желании, канал
результатов):

```bash
nano private.txt          # сохранить: Ctrl+O, Enter; выйти: Ctrl+X
```

**Шаг 4. Первый запуск.**

```bash
source venv/bin/activate  # «включить» окружение проекта (для Windows: venv\Scripts\activate)
python3 main.py
```

При первом запуске Telegram пришлёт в приложение код подтверждения — введи его
в терминал. Дальше в консоли будут идти строки о подключении, а в папке появится
файл сессии `session_name.session` — он и хранит вход, код больше спрашивать
не будут.

Если написать `python3 main.py` без `source venv/bin/activate`, будет ошибка
`ModuleNotFoundError: No module named 'telethon'` — это значит, что окружение
проекта не включено. Вместо активации можно всегда писать полный путь:
`./venv/bin/python main.py`.

**Шаг 5. Проверьте работу.** Не закрывая бота, зайди в Telegram в любой нужный
чат и напиши `/sum 1h`. Команда из чата исчезнет, а через полминуты в канале
результатов (или в «Избранном») появится разбор.

**Шаг 6. Чтобы работал после закрытия терминала.** Останови бота (`Ctrl+C`),
включи окружение и запусти в фоне:

```bash
source venv/bin/activate
./scripts/start_bot_background.sh     # запускает бота в screen (при необходимости доустановит screen)
```

- посмотреть бота и его логи: `screen -r telegram-chat-analyzer`,
- выйти из просмотра, не останавливая бота: `Ctrl+A`, затем `D`,
- остановить: `./scripts/stop_bot.sh`.

`screen` можно и пропустить: в `scripts/telegram-bot.service.example` лежит готовый
файл службы systemd (запуск при загрузке сервера, перезапуск после сбоев).
При копировании исправь три вещи: пути, имя пользователя и строку запуска —
в ней должна быть программа из окружения проекта, потому что systemd не умеет
`source`:

```ini
ExecStart=/home/ваш_логин/ChatSum/venv/bin/python /home/ваш_логин/ChatSum/main.py
```

Дальше как обычно: `sudo systemctl enable --now telegram-bot`, логи —
`journalctl -u telegram-bot -f`.

**Шаг 7. Дайджест по расписанию.** В любом чате напиши `/sch 08:00 1d` —
каждое утро в 8:00 МСК будет саммари за сутки. Посмотреть расписание —
`/sch_list`, убрать чат — `/unsch`. Время указывается московское.

**Шаг 8. Обновление версии.**

```bash
./scripts/stop_bot.sh
git pull
./scripts/setup.sh
source venv/bin/activate && python3 main.py     # или снова ./scripts/start_bot_background.sh
```

Файл `private.txt` при обновлении не трогается.

</details>

<details>
<summary>Вариант 2. GitHub Actions (без сервера) — пошагово</summary>

Бот будет жить на чужих серверах GitHub: раз в несколько минут запускается
короткая программа, которая забирает твои команды и задачи из расписания.
Свой сервер не нужен.

**Шаг 1. Аккаунт и форк.** Зарегистрируйся на [github.com](https://github.com),
открой [github.com/Hohlas/ChatSum](https://github.com/Hohlas/ChatSum) и нажми
`Fork` — у тебя появится своя копия проекта. **Оставь её публичной**: в публичном
репозитории минуты GitHub Actions бесплатны без ограничений, а в приватном
даётся 2 000 минут в месяц, которых этому боту хватит примерно на сутки
(дежурный работает почти круглосуточно).

**Шаг 2. Скачай свой форк и повтори первые шаги варианта 1.**

```bash
git clone https://github.com/ВАШ_ЛОГИН/ChatSum.git
cd ChatSum
./scripts/setup.sh
nano private.txt          # ключи Telegram и Gemini
```

**Шаг 3. Сгенерируй строку сессии** — ею бот будет входить в Telegram из GitHub:

```bash
./venv/bin/python tools/gen_session.py
```

Спросит код из Telegram и сохранит строку в файл `telegram_session.txt`
(он тоже не попадает в репозиторий). Копировать её руками не нужно —
следующий шаг заберёт файл сам. **Не запускай эту команду, пока где-то
работает бот из варианта 1:** два входа с одной сессией мешают друг другу.

**Шаг 4. Установи `gh` и залей ключи в GitHub.**

```bash
# Ubuntu/Debian: sudo apt install -y gh
# Windows: winget install --id GitHub.cli    macOS: brew install gh
gh auth login                    # войти в свой аккаунт GitHub
./scripts/push_github_secrets.sh # заливает ключи из private.txt в настройки репозитория
```

Скрипт сам определит твой форк по `git remote`, покажет только имена ключей
и их длину (значения не печатает) и положит секреты в GitHub Secrets,
а настройки модели — в Variables. Проверить без записи можно так:
`./scripts/push_github_secrets.sh --dry-run`.

**Шаг 5. Включи Actions в форке.** В свежем форке задачи выключены — GitHub
делает так специально. Открой вкладку `Actions` в своём репозитории и нажми
зелёную кнопку вида «I understand my workflows, go ahead and enable them».
Без этого шага дальше ничего не запустится.

**Шаг 6. Задай расписание.** Открой файл `SCHEDULE.txt` — каждая строка это
`id-чата|время|период` (время московское):

```text
-1001234567890|08:00|1d      # дайджест этого чата каждый день в 8:00 МСК
-1001987654321|21:30|1d+     # «+» — результат ещё и в исходный чат
-1001111222333|06:30|1d-     # «-» — вместо Telegraph сообщение в канал
```

Отправь изменения:

```bash
git add SCHEDULE.txt
git commit -m "schedule"
git push
```

Тот же результат без компьютера — из Telegram в канале результатов, сообщением
без слеша: `08:00 sum1d t.me/имя_чата`. Бот запишет строку в `SCHEDULE.txt`,
сам закоммитит и запушит. Название чата в ссылке — латиницей (как в адресе
`t.me/...`), кириллица не подойдёт. Посмотреть расписание — сообщение `sch`,
убрать чат — `unsch`.

**Шаг 7. Первый запуск и проверка.** В репозитории: вкладка `Actions` →
слева `ChatSum scheduled summaries` → кнопка `Run workflow`. Через минуту
открой появившийся запуск и загляни в строку `Run due summaries` — там видно,
что бот делает и не ругается ли он на ключи.

**Шаг 8. Дальше он просыпается сам** — пять раз в час (в 07, 19, 33, 46 и 58
минут, время UTC) и остаётся дежурным примерно пять с половиной часов, поэтому
команды из канала подхватываются за десятки секунд (опрос раз в 30 секунд).
Если GitHub в момент запуска перегружен, отдельные тики могут задержаться
или выпасть — на ежедневные дайджесты это не влияет, они догоняются
следующим дежурным.

**Как отдавать команды.** Писать их нужно в канал результатов, без слеша:
`sum50 t.me/имя_чата` (разбор последних 50 сообщений), `sum 1d`, `copy 200`.
Если канал разбит на темы (форум), можно писать прямо в тему нужного чата —
тогда ссылка не нужна. Сообщение с командой бот удаляет после выполнения;
если что-то не получилось, он попробует ещё раз (до 5 попыток) и напишет
об ошибке. Сообщение `help` покажет краткую справку прямо в канале.
Слеш в канале не используй: `/<что-то>` зовёт чужих ботов и до нашего
дежурного не доходит.

**Если надолго останавливаешь бота:** GitHub выключает расписание после
60 дней без активности в репозитории. Дежурный сам пишет свои отметки в ветку
`state`, так что обычно этого не происходит; но если увидел, что запусков давно
нет, загляни в `Actions` и включи задачу заново кнопкой `Enable workflow`.

</details>

<summary>Справка: канал для результатов и id чата</summary>

Куда попадают саммари:

- `TELEGRAM_GROUP_ID` не задан → результаты в «Избранное» (Saved Messages).
- Задан приватный канал → результаты там, по одной теме на каждый чат-источник
  (если канал включён как форум, темы создаются автоматически).
- Задать ID можно для любого канала или супергруппы, куда ты сам можешь писать.

Как узнать ID, два способа:

1. Через бота `@username_to_id_bot`: напиши ему ссылку на свой канал —
   он покажет ID вида `-1001234567890`.
2. Скриптом из проекта (после заполнения `private.txt`, спросит код Telegram):

```bash
./venv/bin/python tools/get_channel_id.py
```

Скрипт напечатает список твоих каналов и супергрупп с ID — нужный скопируй
в `private.txt` в строку `TELEGRAM_GROUP_ID`.
